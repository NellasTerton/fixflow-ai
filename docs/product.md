# FixFlow AI: продукт

## Что это

FixFlow AI — AI-диспетчер и операционная система для выездных сервисных
компаний. Публично доступно тестовое рабочее пространство с вымышленными
данными; это не система для обработки реальных клиентов.

Компания оказывает три вида услуг:

1. ремонт бытовой техники;
2. сантехнические работы;
3. установка и обслуживание кондиционеров.

## Основной сценарий

Клиент пишет в чат → система определяет категорию и услугу → отвечает по
базе знаний через RAG → собирает контактные данные → предлагает свободное
время → создаёт заявку и бронирование → заявка сразу видна в рабочем
пространстве → уходит webhook в Make → Make маршрутизирует событие,
отправляет Telegram-уведомление и подтверждает доставку обратным callback.
Отложенные события (follow-up по заявке без бронирования, напоминание перед
выездом) Make запрашивает по расписанию через отдельный endpoint.

Весь путь реализован и проверен в production сквозными тестами: гибридный
чат использует Claude для классификации и извлечения данных, а
детерминированный сервер независимо проверяет каждое поле, сохраняет
сообщения, создаёт заявку, бронирует слот и показывает результат в рабочем
пространстве без задержки. При недоступности LLM сценарий продолжает
работать без неё. RAG отвечает на информационные вопросы только по базе
знаний компании, отклоняет неподтверждённые числа и показывает источники.

## Пользователи

- Клиент проходит сценарий обращения через чат или обычную форму.
- Диспетчер видит заявки в рабочем пространстве и историю их обработки.
- Разработчик или нанимающий менеджер оценивает архитектуру, RAG и
  автоматизации через `/workspace/ai-runs` и `/workspace/automations`.

## Текущие ограничения

- Полноценной авторизации сотрудников пока нет.
- `/workspace/leads` доступна публично без логина и только для чтения.
- Реальные персональные данные запрещены.
- Телефоны и адреса в рабочем пространстве маскируются.
- Neon PostgreSQL и pgvector подключены; Claude включается через server-only
  env, а RAG использует только `.md`/`.txt` документы из `knowledge/demo`.
  Make.com владеет Telegram-доставкой и отложенными автоматизациями.

## Критерий успеха

Посетитель может пройти весь путь от сообщения до заявки, увидеть результат
в рабочем пространстве и — если интересна техническая часть — понять, где
Next.js заканчивает работу, а автоматизация Make начинает её.
